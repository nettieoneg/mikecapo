01 How a request travels

A requester fills in one short form. Everything after that is automatic — no one forwards anything, and nothing sits in an inbox waiting to be passed along.

One number, one request. Each request gets a permanent number — EWR #1, #2, #3 — assigned automatically and never reused. Quote it in any conversation about that request.

03 What an approver does

  1. 01

    Gets a notification

    By email, and in the Approvals area of Microsoft Teams. It contains the full request — what, where, why, need-by date and estimated cost — so there is nothing to go and look up.

  2. 02

    Clicks Approve or Reject, adds a comment

    No new system to learn and no password to remember. The comment is saved with the request and is what the requester sees.

  3. 03

    That's it

    The record updates and the requester is told the outcome automatically. Nobody has to email anyone to close the loop.

04 Not in the first version

Named here so there are no surprises. Each of these is a deliberate omission to get the workflow running, not an oversight — and each can be added once the routing above is trusted.

  • LATER Spend thresholds. A $2,000 request and a $200,000 request follow the same path. Approvers escalate as they do today.
  • LATER Automatic reminders. Nothing chases a late approver. A pending list is reviewed weekly instead.
  • LATER Attachments. No drawings or photos on the form; an approver asks for them if needed.
  • LATER Editing a submitted request. A rejected request is resubmitted rather than corrected in place.
  • LATER Cover for absence. If an approver is away, their request waits. Add a backup name above if that is unacceptable for a given row.
